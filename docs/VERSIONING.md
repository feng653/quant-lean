# 版本号与线路管理

## 版本号规则（自动分配，无需人懂 SemVer）

每提一个新需求（issue），回答一个问题：**"这个需求会改变接口/行为吗？"**

| 回答 | 版本增量 | 例子 |
|---|---|---|
| 否（纯重构、加测试、修 bug） | +0.0.1 | v0.3.0 → v0.3.1 |
| 是（改端点、删功能、改数据结构） | +0.1.0 | v0.3.x → v0.4.0 |

- 一个版本 = 一个需求 = 一个 issue = 一个方向。需求混装时拆成多个 issue。
- 版本号记录在 issue 标题（如 `[v0.4.0] main.py 抽层`）和 `docs/todo/TODO_INDEX.md`。

## 线路模型（trunk + tag + 按需 hotfix）

```
master（开发线）─── 只收"CI 绿 + 快照符合声明"的合并 → 永远可跑
   │ 每版本合并后：用户手工验收一次 → 打 tag
   ▼
v0.3.0 ──v0.3.1── v0.4.0 ── …（tag = 稳定线，只从 tag 部署）
   │ 已发布版本出问题：
   ▼
hotfix/v0.4.0-xxx ← 从该 tag 切出 → 修 → 合回 master → 打 v0.4.1
```

| 线路 | 是什么 | 保证 |
|---|---|---|
| 开发线 | master + 各 agent 分支 | master 常绿（合并门禁）；分支相互隔离 |
| 稳定线 | tag v0.x.y | 只从 tag 部署；tag 不可变；修复走 hotfix 分支 |
| 日常使用 | 最新 tag 或 master | 永远有可用的稳定版本兜底 |
