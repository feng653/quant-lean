# 代码与接口审查结论

## 结论

本轮已经把项目从“页面和接口形似完整，但多处依赖虚拟数据或松散字段”收口为可验证的模拟盘闭环。核心事实来源在后端数据库，前端只读取真实 API；实验、部署、组合、信号、订单、持仓和净值之间已有明确的标识、权限和时间语义。

当前定位仍是**日频模拟盘**，不是券商实盘系统。实盘网关、分钟级撮合、交易所回报对账和生产级数据库不在本轮范围内。

## 已处理的主要问题

| 层次 | 原问题 | 处理结果 |
|------|--------|----------|
| 行情 | 数据源和缓存主要按收盘价工作，无法保证开盘成交 | 统一为 `(code, field)` OHLCV 面板；旧缓存自动重建 |
| 回测 | 信号日和成交日边界不严格，存在收盘价成交回退 | 固定为 T 日信号、T+1 开盘成交、收盘估值；缺失开盘价不成交 |
| 模拟盘 | 前端使用虚拟订单、信号、持仓和净值 | 后端持久化真实运行批次、订单、持仓快照和净值；前端全部接真实 API |
| 实验 | 完成状态可能没有净值/成交/指标产物 | 任务原子落库全部产物，失败写明原因，任务可恢复 |
| 策略 | 注册中心复用有状态策略实例，参数和模型可能串扰 | 每次执行获取独立实例；训练数据截至信号日 |
| 组合 | 滑块浮点权重不精确，也无法表达约束和现金 | 使用整数基点；支持现金、上下限、锁定、风险预算、预览、草稿和发布 |
| 接口 | 前后端字段靠 `any` 和兼容分支拼接，OpenAPI 信息不足 | 关键响应增加 Pydantic 模型，前端类型与真实响应对齐 |
| 并发 | WebSocket 消费竞争，任务状态恢复不完整 | 每连接独立队列广播；后台任务原子认领并恢复中断任务 |
| 权限 | refresh token 可误作 access token，WS/AI 资源校验不足 | 区分令牌类型，停用用户立即失效，WS 和资源接口校验权限/归属 |
| 运维 | 数据库只靠建表、CI 容易假通过 | 增量迁移；后端 lint/单元/集成和前端 lint/测试/构建均为必需检查 |

## 当前接口边界

1. 策略在 T 日收盘后只读取不晚于 T 的数据。
2. T+1 必须是后续交易日，订单只能使用该日开盘价；开盘价无效则记录拒单。
3. T+1 收盘价用于持仓市值和净值，不用于替代成交价。
4. 组合配置以 10000 基点为满仓，剩余权重是现金；发布前必须通过服务端校验。
5. 非管理员只能访问自己的实验、部署、组合、任务和模拟运行。
6. 关键列表、详情和分页响应以 OpenAPI 模型为契约，前端不生成业务假数据。

## 已知限制与后续路线

以下是产品能力边界，不是本轮遗留的虚拟实现：

1. **数据偏差治理**：预设指数池使用当前成分股时仍可能有幸存者偏差。下一阶段应接入历史成分股、复权因子、停复牌和涨跌停状态。
2. **撮合精度**：当前是日频开盘价撮合。下一阶段应加入成交量约束、滑点曲线、部分成交、停牌/一字板规则，再考虑分钟级行情。
3. **生产基础设施**：SQLite 和单进程任务工作器适合单机模拟。多人生产部署应迁移 PostgreSQL、Redis/Celery，并增加分布式锁和可观测性。
4. **实盘接入**：需要单独设计券商适配层、订单状态机、幂等委托号、撤单、成交回报、日终对账和紧急停机；不能直接复用模拟盘的“已成交”假设。
5. **浏览器验收**：现有测试覆盖计算、API 契约和前端分配逻辑；仍应补充 Playwright 主流程、可访问性和视觉回归。
6. **安全运维**：生产环境需使用外部密钥管理、HTTPS、审计日志留存、登录限流和定期依赖漏洞扫描。
7. **尚未完成的扩展功能**：抽象组合策略已存在，但等权/风险平价/动量组合的具体实现、定时重训练调度器、模型历史管理 UI、独立 AI 交互组件、股票筛选器和自定义股票池管理仍是明确的 roadmap 项，文档不再将它们标为完成。

建议按上述顺序推进：先消除数据偏差，再提升撮合真实性，随后迁移生产基础设施，最后接券商实盘。这样每一层都能在进入更高风险阶段前被独立验证。
