# 项目哲学（宪法，七条）

> 生效日期：2026-08-03 ｜ 项目：`feng653/quant-lean`（旧仓库 `feng653/quant-platform` 已冻结存档）

**一句话：这是一个人的量化工作台，不是多用户的金融系统。** 所有功能只回答一个问题：
"它是否在保护我的资金安全、数据可信或结果可复现？"——是，就保留并做严谨；否，就删掉或做最简。

| # | 宪法 | 大白话 | 现状对照 |
|---|---|---|---|
| 1 | 一人用就按一人用设计 | 登录只有"自己 vs 访客"两档，无审批流 | 14 权限 → 2 档；研究晋级流 → 删 |
| 2 | 三层金字塔，不搞四层 | 数据 → 实验 → 模拟盘；实盘不做，架构上不留位置 | execution/ 目录 → 删 |
| 3 | 每层只有一个出入口（单一事实源） | 价格一套存储；回测一个引擎；工具函数各一份 | 5 套价格→1；35 份哈希→1；15 份时间函数→1 |
| 4 | 严格在关键点，简单在非关键点 | 关键点只有 3 个：防前视/防脏数据、任务幂等、实验可复现 | 10 道关卡→3 道；QA 认证/能力令牌/Ed25519→删 |
| 5 | 没有"将来可能用到" | 从没被调用的端点/功能/页面就是负担 | 80 个零使用端点、远程训练 → 删 |
| 6 | 一屏能讲清的功能才允许存在 | 文件 ≤400 行；策略 ≤200 行 | price_ledger.py 4150 行 → 拆 |
| 7 | 契约自动锁定，不用人肉回归 | 响应结构快照，改动 CI 自动报红 | 181 端点 → 全部锁快照 |

## 决策判据（任何改动先过此问）

1. 这个功能是为"实盘级"建的吗？个人场景不需要 → 删或最简。
2. 这个功能保护资金/数据/复现吗？是 → 保留并做严谨。
3. 全项目有没有第二份同样的实现？有 → 收敛到一份。
4. 这个端点/页面有人用吗？没有 → 删除。
