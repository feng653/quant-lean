# 项目哲学（宪法，七条）

> 生效日期：由初始化决定 ｜ 项目：`{{OWNER}}/{{REPO}}`

**一句话：这是一个人的工作台，不是多人系统。** 所有功能只回答一个问题：
"它是否在保护我的资金安全、数据可信或结果可复现？"——是，就保留并做严谨；否，就删掉或做最简。

| # | 宪法 | 大白话 | 落地检查（每季度核对） |
|---|---|---|---|
| 1 | 一人用就按一人用设计 | 登录只有"自己 vs 访客"两档，无审批流 | 权限 ≤2 档 |
| 2 | 三层金字塔，不搞四层 | 核心链路只保留必要层级，不预置不做的东西 | 无空壳目录/占位架构 |
| 3 | 每层只有一个出入口（单一事实源） | 每类数据一套存储；每个引擎一个实现；工具函数各一份 | 无第二份同义实现 |
| 4 | 严格在关键点，简单在非关键点 | 关键点只有 3 个：防脏数据、任务幂等、结果可复现 | 关卡数 = 关键点数 |
| 5 | 没有"将来可能用到" | 从没被调用的端点/功能/页面就是负担 | 零使用功能 = 删除候选 |
| 6 | 一屏能讲清的功能才允许存在 | 单个文件 ≤400 行；核心模块拆分可见 | 最大文件 <400 行 |
| 7 | 契约自动锁定，不用人肉回归 | 响应结构快照，改动 CI 自动报红 | 全部端点锁快照 |

## 决策判据（任何改动先过此问）

1. 这个功能是为"多人/企业级"建的吗？个人场景不需要 → 删或最简。
2. 这个功能保护资金/数据/复现吗？是 → 保留并做严谨。
3. 全项目有没有第二份同样的实现？有 → 收敛到一份。
4. 这个端点/页面有人用吗？没有 → 删除。
