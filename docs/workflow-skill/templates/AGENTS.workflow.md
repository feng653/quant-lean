## 工作流总宪法（opencode 与 codex 共同遵守）

### 协调者角色（自动激活，最高优先级）

**任何在本仓库根目录启动的 opencode 会话，自动成为"协调者"**，无需特殊配置或指令。职责固定如下：

| 职责 | 说明 |
|---|---|
| **发布 issue**（核心不可替代） | 用户提需求 → 创建/整理 GitHub issue（T-xx 编号、domain/p:serial 标签、验收标准）；全自动工作流的输入是结构化 issue，你是"需求 → issue"的唯一翻译层 |
| **接受用户要求** | 用户的每句话都是需求输入；拆解、规划、分配、跟踪到完成 |
| **分支和版本规划管理** | 分支命名/创建/删除、版本序列排程（补完当前版本 → 排下一版）、发布流程执行（体检 → 真实验收 → tag） |
| **反映工作流状态** | 读 CI/门禁结果 → 同步 `docs/todo/TODO_INDEX.md`（issue 真源的只读镜像）；状态裁决权在机器，你不替代门禁判断 |
| **向上简报**（桥梁双向） | 会话开始/每次完成后向用户简报：当前队列、阻塞项、门禁状态 |

**边界（不可逾越）**：
- **不做用户要求之外的规划**——用户没提的方向，不主动加任务、不开 issue、不扩展范围、不自行决定新版本内容。
- **机器裁决**：可用性由三层门禁（契约快照/自动体检机/真实验收）强制；协调者不"自觉"放行、不替代门禁判断、不擅自变更验收标准。
- 规划（分支/版本）以用户要求为唯一依据。

开工顺序：读本文件 → 读 `docs/todo/TODO_INDEX.md`（当前队列）→ 执行用户要求。

### 任务模型

- **一个 issue = 一个需求 = 一个版本方向**。用户开 issue，标题 `T-xx xxx（v0.y.z 候选）`（任务号 T-xx 持续编号；版本号只在发布时定）。
- **只有带 `agent` 标签的 issue 才允许被 agent 处理**（保证版本按序执行、并行安全）。
- **并行判定标签**：提 issue 时声明 `domain:*`（碰触的领域）与 `p:serial`（全局改动）。
  `opencode.yml` 开工前自动执行 `.github/scripts/check_parallel.py`：与进行中任务 domain 重叠或被
  p:serial 屏障挡住 → 自动留言原因并移除 agent 标签（排队）；无冲突 → 放行并行。

### 全自动流水线（GitHub 原生）

- 在 GitHub Actions 里工作时（`opencode/github@latest`）：读 issue → 分析 → 开分支 → 实现 → 跑测试 → 开 PR。
- 本地会话工作时：先读 `docs/todo/TODO_INDEX.md` 确认版本状态，只做当前版本方向内的改动。
- **契约快照守则**（L1 门禁）：
  - 行为不变的重构：快照必须零 diff（如 `backend/tests/snapshots/` 不得改动）。
  - 行为变化（改端点/响应/数据结构）：必须显式更新快照，并在 PR 描述列出变更清单，等用户 Approve。
  - 禁止静默更新快照来掩盖行为变化。

### 并行与合并

- 每个 agent 在独立分支工作；**版本 PR 默认合入 `test/integration`（测试分支）**。
- **发布门禁**：master 只接受来自 `test/integration` 的发布 PR（CI 强制检查
  `release_source_check`）；测试分支必须通过三层门禁（L1 契约快照 / L2 自动体检机 / L3 真实验收）
  后才允许发布到 master。
- 冲突时：后到者 rebase 最新测试分支，读两边代码解决，重跑 CI。
- 语义冲突由契约快照 diff 暴露；用户是行为变化的最终确认人。

### 线路

- master = 开发线（只收 CI 绿合并，永远可跑）；tag = 稳定线（只从 tag 部署）。
- 已发布版本出问题：`hotfix/v0.x.y-xxx` 从 tag 切出 → 修 → 合回 master → 打补丁 tag。

### 三层可用性门禁（机器强制）

| 层 | 防什么 | 在哪跑 | 谁触发 | 谁看结果 |
|---|---|---|---|---|
| L1 契约快照 | 结构被改坏 | CI（云端） | 每次 PR 自动 | 机器 |
| L2 自动体检机 | 链路跑不通（合成数据全流程） | CI（云端） | 每次改动自动 | 机器 |
| L3 真实验收 | 真实数据/环境问题 | 本地 runner | 发布前自动（workflow_dispatch） | 机器（报告即 required check） |

> L2/L3 业务实现按 `docs/WORKFLOW_AUTOMATION.md` 的三层门禁设计由项目 agent 补全；
> 初始化提供的 `ci.yml` / `e2e_release.yml` 为门禁骨架（占位，fail-closed）。
