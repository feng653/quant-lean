## 一、产品定位

平台从“能跑回测的策略集合”升级为一条可审计的量化研发流水线：

1. 策略参数可沉淀为方案，可按策略检索、编辑、设默认并再次调用。
2. 实验明确区分无需训练、一次训练、周期重训练，避免错误的数据窗口配置。
3. 训练、验证、测试和部署使用同一份可复现配置，保留数据、代码、参数和模型指纹。
4. 快策略支持批量参数优化，慢策略支持有预算的搜索与提前终止。
5. 模拟盘与实盘共享订单意图和风控协议，券商 SDK 只作为边界适配器。

## 二、本轮产品决策

### 2.1 参数方案是一等对象

参数不再只附着于某次实验。完成实验后可保存为参数方案，方案包含：

- 策略 ID、完整参数和运行模式；
- 股票池、行业及股票子集；
- 来源实验和保存时的核心指标快照；
- 标签、备注、默认方案状态。

参数方案可独立编辑和删除；删除来源实验不影响已保存的参数快照。创建新实验时可以直接调出方案。

### 2.2 三类训练语义

| 类型 | 判定 | 用户需要配置 | 平台行为 |
|---|---|---|---|
| 无需训练 | `requires_training=false` | 测试区间 | 直接生成信号 |
| 一次训练 | `requires_training=true` 且 `retrain_frequency=never` | 固定训练区间 + 测试区间 | 训练一次，整个测试期复用模型 |
| 周期重训练 | `requires_training=true` 且频率非 `never` | 测试区间 | 每个重训练点仅用当时可见历史自动构造训练窗口 |

Alpha158 LGB/XGB 属于周期重训练；LSTM/Transformer 当前作为一次训练模型使用。后续新增模型必须显式选择该语义。

### 2.3 参数优化不使用普通梯度下降

回测目标通常包含离散参数、交易规则、排名、换手成本和最大回撤，目标函数不连续且不可微，普通梯度下降不适合。产品采用分层方案：

1. 小空间：多参数网格，便于穷举和解释。
2. 跨数量级参数：对数刻度。
3. 中等空间：随机搜索。
4. 昂贵模型：Optuna TPE/贝叶斯优化 + 剪枝。
5. 多目标：收益、回撤、稳定性和成本组成 Pareto 前沿，不把测试集用于选参。

本轮先交付多参数网格、线性/对数/自定义值、100 次预算上限和多维结果视图。

## 三、实验中心路线

### P0：结果可信与可复现

- 参数方案 CRUD、默认方案、来源实验快照和集中管理页。
- 一次训练/周期重训练 UI 与 API 契约。
- 周期训练的 expanding/rolling 窗口及 embargo。
- 参数边界前端提示和后端强校验。
- 行业筛选、股票池浏览、搜索和股票子集选择。
- 模型信息卡展示真实训练窗口、训练次数、样本数、耗时和指标。

### P1：机器学习研究深度

- 独立 validation 段，训练、验证、测试指标并列。
- 标签 horizon、标签形式、裁剪与超额收益定义可配置。
- 预处理链：rank、Z-Score、Robust Z-Score、winsorize、缺失值策略。
- Stock holdout、行业 holdout、Purged K-Fold。
- IC、RankIC、ICIR、Top-K 分层收益、特征重要性和过拟合告警。
- 随机搜索、Optuna TPE、剪枝、优化历史和参数重要性。

### P2：研发治理

- 实验模板版本、参数方案审批与废弃状态。
- 数据集快照、特征缓存和模型卡导出。
- 相同数据/代码/参数指纹去重。
- 组合实验、成本压力测试和容量评估。

## 四、策略产品化

新增策略必须满足：

- 自动注册且 metadata 完整；
- 参数 schema 可用于表单和扫描；
- T 日信号只使用 T-1 日及更早数据；
- 单元测试覆盖参数、信号契约和无前视；
- 策略说明包含适用市场、失效场景和主要风险；
- 可部署策略必须给出最大仓位、调仓频率和所需行情能力。

本轮策略库目标从 10 个扩展到 21 个，覆盖单因子、海龟突破、多因子、排序学习及多策略组合。

## 五、QMT / PTrade 接入路线

### 5.1 安全边界

核心系统只产生标准化 `OrderIntent`，券商适配器负责转换。真实下单必须满足：

1. 显式启用 live 模式，默认关闭；
2. 连接健康、账户一致、交易日历有效；
3. 幂等键防重复下单；
4. 单笔、单标的、日累计和组合风险限制；
5. 先预检，再人工确认或受控自动发送；
6. 订单、回报、撤单和错误完整审计；
7. 断线后先对账，禁止直接重放未知状态订单。

### 5.2 分阶段交付

| 阶段 | 能力 |
|---|---|
| L0 | 适配器协议、SDK 就绪检测、订单本地校验 |
| L1 | 只读账户/持仓/成交同步和模拟对账 |
| L2 | 沙箱/测试账户下单、撤单、回报状态机 |
| L3 | 小资金实盘、人工确认、硬风控和熔断 |
| L4 | 受控自动交易、双机监控、灾难恢复 |

PTrade 常见为券商托管环境，QMT 常见为本机客户端进程；二者的运行拓扑不同，但必须实现相同适配器协议。SDK 未安装、客户端未登录或配置缺失时，系统只能报告不可用，不得降级为“假成功”。

## 六、产品指标

- 首次创建实验成功率；
- 方案复用率和方案到新实验转化率；
- 因参数/日期配置导致的 422 比例；
- 实验可复现率；
- 搜索预算利用率和提前终止节省时长；
- train/valid/test 指标差与过拟合告警率；
- 模拟盘与回测信号一致率；
- 券商对账差异、拒单率、重复订单数（目标为 0）。

## 七、AI 嵌入与诊断修复闭环

`moreneeds.md` 已纳入交付目标，并按以下依赖顺序推进。

### 7.1 AI 基础治理（优先）

- `AiService` 作为所有 AI 端点唯一入口；
- 以端点、规范化输入和数据版本生成缓存键，默认 TTL 24 小时；
- `ai_usage` 记录模型、tokens、耗时和缓存命中；
- 回测分析、调参建议、失败诊断、信号解释和市场解读统一契约；
- 调参建议强制 JSON 响应并与前端类型对齐。

本轮已完成统一服务、24 小时缓存、用量/耗时审计和五个页面嵌入。模型调用仅在
所有外部 AI 请求均由用户显式点击后发生。失败实验不会因服务端配置了 API Key
而自动发送错误栈或策略参数；用户在失败诊断卡中确认后才会请求并保存诊断结果。

### 7.2 研究可信度补强

- 为各股票池下载并缓存基准指数行情；
- 回测写入真实 benchmark 净值，使 Alpha/Beta/IR 生效；
- 映射：CSI300→000300、CSI500→000905、CSI800→000906、CSI1000→000852；
- `all_a/custom` 第一版显式记录以沪深300为默认基准，后续允许实验级覆盖。

本轮已完成指数独立缓存、完整内容指纹、回测 benchmark 落库和相对指标接线。
基准覆盖不完整时仅禁用相对指标，不会改变策略自身收益、波动率和 Sharpe。

### 7.3 失败诊断与修复

1. 保存完整 traceback、实验配置、数据覆盖和策略源码定位。
2. 结构化输出 category、root cause、evidence、fix suggestion、auto-fixable。
3. 仅策略接口/策略代码类问题允许生成修复提议。
4. 第一版 `apply-fix` 仅 admin，必须显示 diff 并由人确认。
5. 应用前创建可恢复备份，应用后扫描、参数校验和冒烟；任一步失败立即回滚。
6. AI 永远不自动确认代码变更，不自动 push，不绕过 Git 审计。

### 7.4 多 Agent 下一批拆分

- AI 后端 agent：cache、usage、service、统一响应契约和 mock 测试。
- AI 前端 agent：共享分析卡、调参建议、失败诊断和信号解释组件。
- Benchmark agent：指数数据源、缓存、池映射及指标链测试。
- 主 agent：数据库迁移、页面接线、权限/安全审查、集成与端到端验证。
