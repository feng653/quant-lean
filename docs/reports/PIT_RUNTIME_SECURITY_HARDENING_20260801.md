# PIT-only 运行链路安全加固记录

> **历史安全快照。** 当时“研究/模拟统一硬门禁”的产品政策已被 2026-08-02 的
> warning-only 研究/模拟边界取代；其中任务输入、秘密、hash、幂等和技术完整性控制仍
> 有效，但不得据此恢复个人 paper 的人工认证阻断。当前边界见 [../ROADMAP.md](../ROADMAP.md)。

> 日期：2026-08-01  
> 范围：PIT 自动采集、后台任务持久化、历史实验复用、相关性分析与部署候选。  
> 结论：本轮关闭的是可由代码关闭的边界问题；生产 PIT、价格账本、权威日历和
> 双时态证据仍为空或不完整，因此正式运行继续 fail-closed，实盘继续锁定。

## 已落地的 18 项可验收小迭代

| # | 加固 | 机器验收 |
|---:|---|---|
| 1 | 任务类型只允许注册白名单 | 未知 `job_type` 在写库前拒绝 |
| 2 | 任务用户、重试次数、父任务 UUID 和显示名有边界 | 非法身份/格式在事务前拒绝 |
| 3 | 任务参数禁止密钥、口令、会话和 token 字段 | 嵌套秘密字段不能进入 SQLite |
| 4 | 参数只接受规范、有限 JSON | NaN/Inf、非字符串 key、任意对象拒绝 |
| 5 | 参数有深度、节点和总字节上限 | 深层/超大 payload 不占用队列和数据库 |
| 6 | 每用户活动任务配额 | 一个账号不能填满全局队列；批量提交原子验额 |
| 7 | job result 有结构和 2 MiB 硬上限 | 超限结果不写入持久状态 |
| 8 | progress 必须是有限数，stage 必须是有界机器标签 | Inf/NaN 和任意长 stage 拒绝 |
| 9 | job 状态迁移单调 | running 不能退回 pending；取消优先于完成/失败 |
| 10 | traceback、消息和 API job 数据脱敏 | JWT、Bearer、口令和本机绝对路径不可见 |
| 11 | PIT 自动采集包 ID 严格校验 | 非 `pitpkg_<32hex>` 不能形成成功任务 |
| 12 | PIT 覆盖区间校验 | 倒置、早于请求或未来 coverage 拒绝 |
| 13 | 隔离产物目录围栏 | checkpoint/queue/report 必须位于 evidence root |
| 14 | 隔离产物拒绝 symlink、空文件和超大文件 | 跨库/替换/资源耗尽路径 fail-closed |
| 15 | 三类隔离产物逐个 SHA-256 与大小绑定 | job 只返回摘要，不返回主机路径 |
| 16 | PIT 自动采集全局去重 | 手工与模拟调度不能并发重复采集同一全局归档 |
| 17 | 历史实验统一计算 PIT reuse eligibility | 清单 hash、身份、PIT timeline、价格 binding、质量、基准交叉核验 |
| 18 | legacy 只读隔离 | 旧实验仍可审计，但不能进入 picker、best、相关性、重跑、调优或部署 |

这些检查都在服务端自动执行，没有新增普通用户表单、复核点击或配置步骤。前端只会
看到结构化拒绝原因，例如 `legacy_experiment_reuse_forbidden`、
`pit_experiments_required` 或 `pit_collection_attestation_failed`。

## 历史数据兼容策略

升级不删除数百条旧实验，也不为它们补写推测的 PIT 证据。实验列表继续显示历史
记录，并增加 `pit_eligible=false`、`legacy_read_only=true` 和稳定的
`eligibility_code`。任何候选用途都重新解析并校验不可变 manifest；仅有
`status=completed`、Sharpe 或净值曲线不构成复用资格。

这避免了两类危险兼容：一是把旧收益混入策略相关性/组合构建，二是从旧实验复制
参数或模型后绕过新 PIT 创建门禁。历史审计可用性与正式研究资格被明确分离。

## 仍未关闭的高风险项

1. 生产 PIT master、双价格账本、权威交易日历/停牌/公司行为证据尚未形成完整
   激活链；不能通过降低门槛解决。
2. `known_at` 修订时间仍缺真正双时态供应链，回补数据尚不能证明在历史决策时已知。
3. SQLite 与本地文件不具备 WORM、跨主机共识或多库原子提交；拥有主机写权限的
   对手仍可同时修改数据库和文件，需异地签名摘要与对象保留锁。
4. API 中仍有部分旧只读/运维路由把底层异常拼入 5xx 文本；本轮已保护任务主链，
   其余路由需要统一异常 envelope 后再关闭调试细节。
5. job 配额已限制活动数量，但用户级存储、导出、WebSocket 慢客户端和累计历史
   保留配额尚未统一。
6. 模型仍可能使用 joblib/PyTorch 可执行反序列化；应迁移到受限的非可执行格式。
7. 任务、实验、数据包、审批、部署之间尚无贯穿全链的单一 correlation ID 与异地
   每日签名审计根。
8. 网络最小暴露、生产 API 文档关闭、MFA/refresh token 轮换、异机加密备份和外部
   告警仍需部署级验收。
9. 价格/成员/行业等多库查询缺一致读取快照；在未来并发导入时需要 generation
   token 或迁移到支持一致快照的数据库。
10. 本轮不自动激活任何证据。独立复核、签名日历、四 scope receipt 和 activation
    仍是必要的人机职责分离边界。

在以上外部与架构风险关闭前，`ready=false` 和“无 PIT 数据时零正式实验”是正确
行为，不能把测试 fixture 或代码门禁数量解释为研究数据已经可信。
